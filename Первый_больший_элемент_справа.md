# Первый больший элемент справа: монотонный стек

В новом решении программа разделена на три функции:

- `read_numbers()` — читает числа из файла;
- `find_next_greater_indices()` — решает задачу;
- `print_indices()` — выводит ответ.

В `main()` остались выбор файла, вызовы функций и обработка ошибок.

Сначала разберём саму задачу, затем каждую часть кода.

### Что нужно найти

Для каждого числа `a[i]` нужно найти **первое справа число, которое строго больше него**, и вывести его номер.

Например:

```text
Номера:   1  2  3  4  5  6
Числа:    2  1  5  3  4  6
Ответ:    3  3  6  5  6  0
```

Почему:

- для `2` первое большее справа — `5`, его номер `3`;
- для `1` — тоже `5`, номер `3`;
- для `5` — `6`, номер `6`;
- для `3` — `4`, номер `5`;
- для `4` — `6`, номер `6`;
- для `6` большего справа нет — выводим `0`.

**Ищем ближайшее подходящее число, а в ответ записываем его номер.**

### Подключённые библиотеки

```cpp
#include <fstream>
```

Для чтения из файла через `std::ifstream`.

```cpp
#include <iostream>
```

Для вывода результата через `std::cout` и сообщений об ошибках через `std::cerr`.

```cpp
#include <stdexcept>
```

Для исключений `std::runtime_error`.

```cpp
#include <vector>
```

### Чтение чисел: `read_numbers()`

```cpp
std::vector<long long> read_numbers(const char* path) {
```

Функция получает путь к файлу и возвращает массив прочитанных чисел.

- `std::vector<long long>` — тип результата;
- `long long` — тип целых чисел;
- `const char* path` — указатель на строку с путём к файлу.

```cpp
std::ifstream input(path);
```

Создаём поток чтения и пытаемся открыть указанный файл.

```cpp
if (!input) throw std::runtime_error("Cannot open file");
```

Если открыть файл не удалось, выбрасываем исключение.

`throw` прерывает обычное выполнение функции. Управление перейдёт в подходящий обработчик `catch`, который находится в `main()`.

```cpp
std::size_t count;
```

Переменная для количества чисел.

`std::size_t` — беззнаковый целочисленный тип, применяемый для размеров и индексов.

```cpp
if (!(input >> count))
    throw std::runtime_error("Expected n followed by n integers");
```

Пытаемся прочитать количество элементов.

Выражение:

```cpp
input >> count
```

читает число из файла. Его результат позволяет проверить состояние потока.

Если чтение не удалось, оператор `!` превращает состояние ошибки в `true`, и выбрасывается исключение.

```cpp
std::vector<long long> numbers(count);
```

Создаём массив из `count` элементов.

Например, если `count == 6`, в массиве сразу существует шесть ячеек с индексами от `0` до `5`.

```cpp
for (auto& value : numbers) {
```

Проходим по всем элементам массива.

- `auto` — компилятор определяет тип автоматически; здесь это `long long`;
- `&` — переменная `value` ссылается на настоящую ячейку массива.

Поэтому запись в `value` изменяет соответствующий элемент `numbers`.

```cpp
if (!(input >> value)) throw std::runtime_error("Missing integer");
```

Читаем очередное число в ячейку.

Если в файле закончились числа или встретился неподходящий текст, выбрасываем исключение.

```cpp
return numbers;
```

Возвращаем заполненный массив.

Например, файл:

```text
6
2 1 5 3 4 6
```

даст результат:

```text
numbers = [2, 1, 5, 3, 4, 6]
```

При выходе из функции файловый поток автоматически закрывает файл.

### Главная идея алгоритма

Будем идти по числам слева направо.

Некоторые уже просмотренные числа пока не получили ответа: справа от них ещё не встретилось ничего большего. **Индексы таких чисел храним в стеке `pending`.**

Когда приходит новое число, оно может стать ответом сразу для нескольких ожидающих элементов.

Например:

```text
Уже встретили: 8, 5, 2
Пришло: 6
```

Число `6` является первым большим справа:

- для `2`;
- для `5`.

Для `8` оно не подходит, поэтому `8` продолжает ждать.

Стек позволяет быстро обработать ожидающие элементы начиная с последнего.

### Заголовок функции алгоритма

```cpp
std::vector<std::size_t> find_next_greater_indices(
    const std::vector<long long>& numbers) {
```

Функция принимает исходный массив и возвращает массив номеров.

```cpp
const std::vector<long long>& numbers
```

означает передачу по константной ссылке:

- `&` — весь массив при вызове не копируется;
- `const` — функция не может изменять его элементы через эту ссылку.

Возвращаемый тип:

```cpp
std::vector<std::size_t>
```

— массив индексов, точнее номеров элементов в принятой нумерации с единицы.

### Массив ответов

```cpp
std::vector<std::size_t> answer(numbers.size(), 0);
```

Создаём столько ответов, сколько исходных чисел, и заполняем их нулями.

Изначально:

```text
answer = [0, 0, 0, 0, 0, 0]
```

Ноль означает: «больший элемент справа не найден».

Если для элемента ответ так и не найдётся, его ноль останется без изменений.

### Стек ожидающих индексов

```cpp
std::vector<std::size_t> pending;
```

Создаём пустой массив, который будем использовать как стек.

Для этого достаточно трёх операций:

| Выражение | Значение |
|---|---|
| `pending.push_back(j)` | Положить индекс на вершину |
| `pending.back()` | Посмотреть индекс на вершине |
| `pending.pop_back()` | Удалить верхний индекс |

Дополнительно:

```cpp
pending.empty()
```

проверяет, пуст ли стек.

**В стеке находятся индексы, а не сами числа.** Индекс нужен, чтобы и получить исходное значение, и записать ответ в правильную ячейку.

Например:

```text
pending.back()          — индекс ожидающего элемента
numbers[pending.back()] — его значение
answer[pending.back()]  — его ответ
```

### Проход по исходным числам

```cpp
for (std::size_t j = 0; j < numbers.size(); ++j) {
```

Последовательно рассматриваем все элементы массива.

`j` — индекс текущего числа, начиная с нуля.

Для массива:

```text
Числа:    2  1  5  3  4  6
Индексы:  0  1  2  3  4  5
```

### Условие обработки стека

```cpp
while (!pending.empty() && numbers[j] > numbers[pending.back()]) {
```

Продолжаем, пока одновременно выполняются два условия:

1. в стеке есть ожидающие элементы;
2. текущее число больше числа, чей индекс находится на вершине.

Оператор `&&` означает логическое «и».

Проверка пустоты стоит первой специально: если стек пуст, вторая часть не вычисляется. Поэтому обращения к `pending.back()` у пустого стека не происходит.

Для удобства условие можно мысленно читать так:

> Пока кто-то ждёт и текущее число больше последнего ожидающего — заполняем ему ответ.

### Запись найденного ответа

```cpp
answer[pending.back()] = j + 1;
```

Для элемента на вершине стека подходящее число найдено на текущей позиции `j`.

Почему `j + 1`?

Внутри массива индексы начинаются с нуля, а в условии номера элементов — с единицы.

Например:

```text
Индекс 2 → номер 3
```

Поэтому в ответ записываем `3`.

```cpp
pending.pop_back();
```

Удаляем обработанный индекс из стека: ответ для него уже найден.

После этого проверяется новая вершина. Текущее число может оказаться больше и неё.

### Добавление текущего индекса

```cpp
pending.push_back(j);
```

После обработки предыдущих элементов текущий индекс тоже кладём в стек.

Для самого `numbers[j]` мы пока не знаем ближайший больший справа: следующие числа ещё не рассмотрены.

### Возврат результата

```cpp
return answer;
```

После полного прохода возвращаем ответы.

Индексы, которые остались в `pending`, относятся к числам без большего элемента справа. Их ответы остаются нулями.

### Пошаговый пример

Исходные данные:

```text
numbers = [2, 1, 5, 3, 4, 6]
answer  = [0, 0, 0, 0, 0, 0]
```

Ниже стек записан **снизу вверх, вершина справа**. Для наглядности показываем значения; в программе хранятся их индексы.

**Пришло `2`, индекс `0`.**

Стек пуст. Добавляем индекс `0`.

```text
Значения в стеке: [2]
answer:          [0, 0, 0, 0, 0, 0]
```

**Пришло `1`, индекс `1`.**

`1` не больше `2`. Никому ответ не найден.

Добавляем индекс `1`.

```text
Значения в стеке: [2, 1]
answer:          [0, 0, 0, 0, 0, 0]
```

**Пришло `5`, индекс `2`, номер `3`.**

На вершине находится `1`:

```text
5 > 1 → answer[1] = 3
```

Удаляем индекс единицы.

Теперь на вершине `2`:

```text
5 > 2 → answer[0] = 3
```

Удаляем индекс двойки.

Стек пуст. Добавляем индекс пятёрки.

```text
Значения в стеке: [5]
answer:          [3, 3, 0, 0, 0, 0]
```

**Пришло `3`, индекс `3`.**

`3` не больше `5`, поэтому просто добавляем индекс.

```text
Значения в стеке: [5, 3]
answer:          [3, 3, 0, 0, 0, 0]
```

**Пришло `4`, индекс `4`, номер `5`.**

```text
4 > 3 → answer[3] = 5
```

Удаляем индекс тройки.

Теперь на вершине `5`, но `4` не больше `5`. Останавливаем удаление и добавляем индекс четвёрки.

```text
Значения в стеке: [5, 4]
answer:          [3, 3, 0, 5, 0, 0]
```

**Пришло `6`, индекс `5`, номер `6`.**

```text
6 > 4 → answer[4] = 6
6 > 5 → answer[2] = 6
```

Оба индекса удаляются. Добавляем индекс шестёрки.

```text
Значения в стеке: [6]
answer:          [3, 3, 6, 5, 6, 0]
```

Числа закончились. Для шестёрки ответ не найден.

### Почему достаточно смотреть только на вершину

В этом состоит важное свойство алгоритма: **значения в стеке расположены по убыванию снизу вверх**, поскольку по условию числа различны.

Например:

```text
[9, 7, 3]
       ↑ вершина
```

Это свойство поддерживается автоматически: перед добавлением нового числа мы удаляем все меньшие значения с вершины.

Если пришло `2`, оно не больше вершины `3`. Значит, оно тем более не больше более глубоких элементов `7` и `9`. Их проверять не нужно.

Если пришло `8`, оно последовательно обработает `3` и `7`, а на `9` остановится:

```text
Было:  [9, 7, 3]
Стало: [9, 8]
```

Такой стек называется **монотонным**.

### Почему находится именно ближайший больший элемент

Идём слева направо.

Когда для ожидающего индекса `i` записывается ответ `j + 1`, выполняется:

```text
j > i
numbers[j] > numbers[i]
```

При этом раньше подходящего числа не было. Если бы оно встретилось, индекс `i` был бы обработан уже тогда.

Свойство убывающего стека гарантирует, что меньшие элементы поверх `i` не помешают: подходящее для `i` число сначала удалит их, а затем дойдёт до `i`.

Поэтому текущая позиция — **первая подходящая справа**, то есть минимальный требуемый `j`.

### Почему сложность `O(n)`, хотя циклы вложены

В коде есть:

```cpp
for (...) {
    while (...) {
        ...
    }
}
```

Но вложенность сама по себе ещё не означает `O(n²)`.

Считаем операции за всё выполнение:

- каждый индекс добавляется в стек ровно один раз;
- каждый индекс удаляется из стека не более одного раза;
- после удаления индекс больше в стек не возвращается.

Всего будет:

```text
n добавлений
не более n удалений
```

Один проход может удалить много элементов, но это уменьшит объём работы следующих проходов.

Суммарное время — **`O(n)`**.

Для строгого амортизационного объяснения можно сказать:

> Каждому индексу при добавлении приписываем оплату двух действий: текущего добавления и возможного будущего удаления. Поскольку индекс добавляется один раз и удаляется максимум один раз, суммарная стоимость операций со стеком линейна.

Здесь стек реализован через `vector`: его `push_back()` имеет амортизированную стоимость `O(1)`, так что общая оценка сохраняется.

Память — **`O(n)`**: массив ответов и стек могут содержать до `n` элементов.

- массив ответов по константной ссылке;
- поток, куда нужно их вывести.

`void` означает, что функция не возвращает значение.

```cpp
std::ostream& output
```

```cpp
for (std::size_t i = 0; i < indices.size(); ++i)
```

```cpp
output << (i ? " " : "") << indices[i];
```


Если `i != 0`, сначала выводится пробел, затем очередной ответ.

Получается:

```text

```

### Как рассказать преподавателю

> Программа разделена на чтение данных, вычисление ответа и вывод. В `main` находятся только вызовы этих функций и обработка исключений.
>
> Алгоритм проходит последовательность слева направо. В монотонном стеке я храню индексы элементов, для которых ещё не найден первый больший справа. Значения этих элементов расположены в стеке по убыванию.
>
> Когда приходит новое число, я сравниваю его с вершиной стека. Пока оно больше, записываю текущий номер как ответ для верхнего индекса и удаляю этот индекс. Затем добавляю текущий индекс в стек.
>
> Поскольку позиции рассматриваются слева направо, найденный больший элемент является ближайшим. Если индекс остался в стеке после прохода, большего элемента справа нет, поэтому ответ равен нулю.
>
> Каждый индекс добавляется один раз и удаляется максимум один раз. Поэтому суммарное время — `O(n)`, несмотря на вложенный цикл. Дополнительная память — `O(n)`.
